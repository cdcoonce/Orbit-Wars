# Plan: Comprehensive Repo Wiki

> Source PRD: [Orbit-Wars #13](https://github.com/cdcoonce/Orbit-Wars/issues/13)

## Architectural Decisions

- **Location:** `docs/wiki/` in the repo root. Subdirectories: `docs/wiki/src/` and `docs/wiki/tests/`.
- **Format:** Hand-authored Markdown; except `config.md` param table which is auto-generated from source.
- **Diagram language:** Mermaid embedded in Markdown — `flowchart`, `sequenceDiagram`, `classDiagram`, `stateDiagram-v2`.
- **Sync:** `docs/wiki/` is source of truth. GitHub Wiki tab is a read-only mirror pushed by CI on every push to main. **Prerequisite:** wiki tab must be manually initialized via GitHub UI before the Action can push.
- **Hook type:** Claude Code `post-edit` hook (fires on Claude's Edit tool calls), not a git hook. Non-blocking warning (exit 0).
- **Config auto-generation:** `docs/wiki/generate_config.py` reads `PARAMS` + `PARAM_SPACE` from `config.py` and regenerates the param table section of `config.md`. Run with `uv run python docs/wiki/generate_config.py` after any Optuna tuning run. Script must raise loudly if PARAMS and PARAM_SPACE keys diverge.
- **Depth standard:** Every function documented at signature + behavior + non-obvious gotchas level.

## Phase 1: Foundation, Architecture Overview & Navigation

**User stories:** 1, 2, 13, 21

### What to build

Establish the `docs/wiki/` directory and deliver the three highest-value orientation pages plus the navigation scaffold.

`Home.md`: system overview, quickstart commands, module inventory table, and a top-level Mermaid `flowchart` tracing the full call chain: `agent(obs)` → `plan_moves` → `classify_own`/`detect_threats` → `plan_expansion` → `step_state` → `score_state`.

`Game-Loop.md`: concept-level deep-dive into a single turn — what happens in each function, in what order, with a `flowchart` diagram showing the branching logic (endgame early-exit, threat-handling path, expansion path).

`Decision-Trace.md`: a single annotated real game turn. Planet states going in, classifier outputs, scoring numbers (greedy vs lookahead), chosen move, and outcome. Makes every abstract concept on every other page immediately concrete.

`_Sidebar.md`: GitHub Wiki navigation panel. Four sections — Overview (Home, Game-Loop, Decision-Trace), Reference (src/ pages), Operations (Tuning-Pipeline, Build), Infrastructure (tests/, sync Action).

## Phase 2: Core Engine Reference

**User stories:** 5, 6, 7, 14, 15, 16, 17, 18, 22, 23, 24, 25

### What to build

Three heavyweight module reference pages covering the core decision engine, plus the config auto-generation script.

`src/strategy.md`: every function in `strategy.py` at signature + behavior + gotchas depth. Includes: planet classification logic with a `stateDiagram-v2` showing transitions (FORTRESS/FACTORY/OUTPOST/THREATENED), the SKIP_COMBOS table with rationale, the aggression ramp formula (min → max over game_length turns), the garrison ramp (early vs settled game), and plan_expansion's greedy scoring formula plus lookahead blend.

`src/lookahead.md`: `SimPlanet`, `SimFleet`, and `GameState` dataclasses with a `classDiagram`, then `step_state`'s six-step simulation order with a `sequenceDiagram` (production → rotate → our fleet → opponent → move → combat). Documents the foothold cost (−1 ship pessimism bias) and the recursion cap (opponent forced to blend=0).

`src/config.md`: prose sections (purpose, how to read, when to regenerate) hand-authored; param table auto-generated by `generate_config.py`. Groups: Planet Classification, Value Classification, Threat Ratios, Send Fractions, Defense, Aggression Scaling, Garrison Ramp, Comets, Endgame, Lookahead.

`docs/wiki/generate_config.py`: reads `PARAMS` and `PARAM_SPACE` from `src/config.py`, emits a grouped Markdown table (key | current value | Optuna range | behavioral impact) into the param table section of `config.md`. Preserves hand-written prose. Raises `ValueError` if PARAMS and PARAM_SPACE keys diverge.

## Phase 3: Supporting Module Reference & Gotchas Index

**User stories:** 4, 8, 9, 10, 11

### What to build

Four smaller module pages, the test suite overview, and a cross-cutting Gotchas index.

`src/agent.md`: the `obs` dict structure (all keys, types, semantics), the `initial_planets` global cache (why it exists, when it's set), and what `plan_moves` receives.

`src/math_utils.md`: the fleet speed curve formula and log shape (1 ship → 1.0, 1000 ships → 6.0), `predict_planet_position` rotation logic (orbiting vs stationary: orbital_radius ≥ 40), the sun-crossing guard (SUN_RADIUS=10, CENTER=50,50), and `turns_to_arrive`.

`src/comets.md`: how `comet_value_multiplier` scales effective production, and why a multiplier < 1 makes comets less attractive than raw production suggests.

`src/endgame.md`: the exact conditions for `should_play_defensive` (turn threshold AND lead margin), the ZeroDivisionError guard (enemy_ships == 0 → False), and what "defensive mode" means (only threat-response moves emitted).

`Gotchas.md`: a single scannable index of every non-obvious behavior across all modules — gotcha name, one-line description, link to the module page with full explanation. Written last so all module pages exist to link to.

## Phase 5: Maintenance Automation

**User stories:** 19, 20

### What to build

Two automation artifacts that keep the wiki from drifting.

**GitHub Action** (`.github/workflows/sync-wiki.yml`): triggers on push to main, copies `docs/wiki/` contents to the wiki remote (`wiki.git`), and force-pushes. Requires a `WIKI_TOKEN` secret (GitHub PAT with minimum `repo` scope for private repos, `public_repo` for public repos). Uses descriptive step names for diagnosability.

**Claude Code post-edit hook** (`.claude/hooks/`): fires when Claude edits any `src/*.py` file via the Edit tool. Warns (non-blocking, exit 0) if the corresponding `docs/wiki/src/{module}.md` has not been edited in the same session. Prints the specific src/ file that changed and the wiki page to update.

**Prerequisite (manual step):** Before the Action can run, the GitHub Wiki tab must be initialized by creating at least one page via the GitHub UI (`github.com/{repo}/wiki`). Document this in the Action's README comment.

### Acceptance Criteria

- [ ] GitHub Wiki tab initialized manually (prerequisite documented in `.github/workflows/sync-wiki.yml` header comment)
- [ ] `.github/workflows/sync-wiki.yml` exists, triggers on push to main, and uses `WIKI_TOKEN` secret
- [ ] Action comment documents minimum PAT scope (`repo` for private, `public_repo` for public)
- [ ] Action copies only `docs/wiki/` contents (not full repo) to wiki.git
- [ ] Action uses descriptive step names (not "Run step 1")
- [ ] Claude Code post-edit hook warns when a `src/*.py` file is edited without the corresponding wiki page
- [ ] Hook exits with code 0 (non-blocking)
- [ ] Hook output names the specific src/ file and the wiki page to update
